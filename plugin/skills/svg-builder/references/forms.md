## フローチャート

順を追う処理、原因と結果、判断の分岐。

**この形式に固有のルール:**

- 向きは 1 つだけ。すべて上から下、またはすべて左から右。軸が混ざると 2 つの図が争っているように
  読める。
- 1 つの図にノードは最大 4〜5 個。それ以上は分割する。
- 段の中では箱の高さを揃える。1 行なら 44px、2 行なら 56px。
- ひし形の判断ノードは、図の中に判断が 2 つ以上あるときだけ。rect の中にひし形が 1 つだけあると
  ノイズになる。出口を 2 つラベル付けした rect のほうがたいてい明快。

1 行のノード:

```svg
<g>
  <rect x="100" y="20" width="180" height="44" rx="8"
        fill="#E1F5EE" stroke="#0F6E56" stroke-width="0.5"/>
  <text x="190" y="42" text-anchor="middle" dominant-baseline="central"
        fill="#085041" font-size="14" font-weight="500">Validate token</text>
</g>
```

2 行のノード。タイトルとサブタイトルで塗りのストップが違う点に注意:

```svg
<g>
  <rect x="100" y="20" width="200" height="56" rx="8"
        fill="#E1F5EE" stroke="#0F6E56" stroke-width="0.5"/>
  <text x="200" y="38" text-anchor="middle" dominant-baseline="central"
        fill="#085041" font-size="14" font-weight="500">Auth service</text>
  <text x="200" y="56" text-anchor="middle" dominant-baseline="central"
        fill="#0F6E56" font-size="12">Verifies the JWT</text>
</g>
```

ラベルなしのコネクタ。意味は送り元と送り先から伝わる:

```svg
<line x1="200" y1="76" x2="200" y2="120" stroke="#888780" stroke-width="0.5"
      marker-end="url(#arrow)"/>
```

**判断の分岐**は出口にラベルが要り、これが「矢印にラベルを付けない」ルールの例外。線の脇に 8px
ずらして置き、ストロークの上には置かない:

```svg
<text x="212" y="98" fill="#5F5E5A" font-size="12">yes</text>
```

## 構造図

ものの中にあるもの。何がどこに*住んでいる*かが要点。

- 最も外側のコンテナ: 大きな角丸の rect、`rx="16"` から `rx="24"`、最も明るい塗り、0.5px の枠線、
  ラベルは内側の左上か上中央。
- 内側の領域: `rx="8"` から `rx="12"`、親とは**別のランプ**。親子で同じランプを使うと塗りが同一に
  なり、示したい階層が平らになる。
- すべてのコンテナの内側に最低 20px のパディング。文字や内側の領域がコンテナの縁に触れてはならない。
- 入れ子は最大 2〜3 階層。それより深いと 680px では読めない。
- 外部からの入力はコンテナの*外*に置き、矢印を内側に向ける。出力は外に置き、矢印を外側に向ける。

**コンテナのラベルとの衝突**がこの形式の代表的なバグ。コンテナの左上に置いたラベルが、コンテナに入る
最初の縦のコネクタに横切られる。ラベルを 2 つの入口の*間*の隙間に置く（先に入口の x 座標を計算し、
最も広い隙間を見つけ、その中央にラベルを置く）か、ぶつからなくなるまでラベルを短くする。

```svg
<rect x="40" y="282" width="600" height="196" rx="16"
      fill="none" stroke="#888780" stroke-width="0.5" stroke-dasharray="4 4"/>
<text x="244" y="304" text-anchor="middle" fill="#5F5E5A" font-size="12">Kafka cluster</text>
```

ラベル付きの破線の rect のほうが、雲やサーバータワーやラックのアイコンを描くよりはるかに「境界」として
読める。ハードウェアの絵ではなく、構成を描く。

## 説明図

直感を作る。空間の配置が意味を担い、ラベルは注釈にすぎない。

**物理的な主題**は、それ自体を単純化したもの（断面図やカットアウェイ）にする。給湯器は背の高い角丸の
rect の下にバーナーの棒。肺は空洞の中の枝分かれした木。

**抽象的な主題**には幾何を発明する。形のないものに形を与えるのであり、その形*こそ*が説明になる。

| 概念 | 幾何 |
|---|---|
| ハッシュテーブル | 漏斗がアイテムを一列のバケツにばらまく |
| コールスタック | 文字どおり積み上がって伸び縮みするフレーム |
| attention | 1 つのトークンから他の全トークンへ、重みで太さの変わる線が扇状に伸びる |
| 勾配降下法 | 等高線の面、ボール、歩みの軌跡 |
| 埋め込み | 2 次元空間で群れをなす点 |
| TCP | 2 つの端点、飛んでいる番号付きパケット、戻ってくる ACK |

**他の形式と変わる点:**

- 自由な形が前提。`<path>`、`<ellipse>`、`<polygon>`、曲線。角丸の rect に限らない。
- レイアウトはグリッドではなく主題の比率に従う。温度計は縦長で細く、地質断面は横長で平たい。
- **形は奥行きのために意図的に重ねてよい。** タンクに入るパイプ、層を貫いて扇状に伸びる線。ソースの
  順序を重なり順にする。
- **文字は決して重ねない。** 重ねてよいのは形だけ。すべてのラベルは最寄りのストロークから 8px の空きが
  要り、衝突は*ラベルを動かして*解決する。ラベルの背後に背景の rect を置いて解決しない。
- 色はカテゴリではなく強度をエンコードする。`color.md` を参照。

**忠実度の上限:** これらは模式図である。`<path>` のセグメントが 6 本ほどを超えるなら単純化する。炎は
三角形 3 つであって、火そのものではない。正確な輪郭より、見分けのつくシルエットが常に勝つ。輪郭を
丁寧になぞっているなら、やりすぎている。

**ラベルの配置:** 片側を選び、すべてのラベルをそこに置く。680px では、描画に加えて両側にラベルの列を
置く余地はない。既定は右側で `text-anchor="start"`、140px を確保し、0.5px の破線の引き出し線と
アンカー地点の 2px の点でつなぐ。

```svg
<line x1="440" y1="250" x2="468" y2="300" stroke="#888780" stroke-width="0.5"
      stroke-dasharray="2 2"/>
<circle cx="440" cy="250" r="2" fill="#888780"/>
<text x="474" y="304" fill="#5F5E5A" font-size="12">Thermostat</text>
```

**インタラクティブを優先する。** 実際のシステムに操作部があるなら、図にもその操作部を与える。
サーモスタットはスライダーに、キャッシュのヒット率はドラッグに、入力トークンはクリック可能に。操作
できる断面図は、眺めるだけのものよりはるかに多くを教える。

## チャート

変数ごとにエンコーディングは 1 つ。位置が先、次に長さ、それから面積。量を面積だけで表さない。読み手は
面積を系統的に過小評価する。

- 棒グラフの軸は 0 から始める。折れ線は切り取ってよいが、軸にそう明記する。
- 軸に単位を付ける。単位のない数字はデータではない。
- 系列は右端に直接ラベルを付け、読み手が照合しなければならない凡例を出さない。
- グリッド線はグレーの 100 ストップ、0.5px、マークの背後。見えるが決して競わない。
- 表示する数字はすべて丸める。

データが本当に大きい、またはインタラクションが要るなら、そう伝えて、何百ものマークを手で置く代わりに
プロットライブラリを勧める。

## ステッパー（循環とステージ向け）

最後のステージが最初に戻るとき（クエン酸回路、イベントループ、マーク＆スイープ、TCP の再送）、直感は
リングを求める。**リングは描かない。** このスキルの間隔の計算はすべて直交座標系で、円の周りを回る箱の
衝突判定はない。ステージごとの入力が、自分が入力する先のステージに乗り、ラベルがリングの上に座る。

インライン SVG を使った HTML のステッパーを作る。ステージごとに 1 パネル、位置を示す点（● ○ ○ ○）、
最後のステージから最初に戻る「次へ」。**その折り返しがループである。** 各パネルが自分の入力と生成物を
持つので、キャンバスを共有せず何も衝突しない。

直線的な SVG（ステージを一列に並べ、1 本の曲がった戻りのパス）に戻すのは、全体で入力と出力が 1 つずつ
で、ステージごとに示す詳細がないときだけ。
