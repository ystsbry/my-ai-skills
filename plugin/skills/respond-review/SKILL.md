# レビュー指摘対応スキル（respond-review）

自分の PR に付いたレビューコメントを読解し、**トリアージ → 修正実装 → メンション付き返信文の作成 → 投稿 → PR本文更新**までを一連で行います。

## 入力

```
# Claude Code（ybaba プラグイン経由）
/ybaba:respond-review <PR番号 or PR URL>（省略時はカレントブランチのPR）

# OpenAI Codex CLI
$ybaba:respond-review <PR番号 or PR URL>    # marketplace 経由のプラグイン
$respond-review <PR番号 or PR URL>          # ~/.agents/skills/ fallback 導入時
```

レビューコメントが会話にペーストされた場合は、それを直接入力として扱ってよい（その場合も投稿先スレッドの特定には gh を使う）。

---

## ステップ1: レビューコメントを収集する

```bash
# PR の特定（省略時）
gh pr view --json number,title,url,body

# レビュー本体とインラインコメント（スレッド）を取得
gh api repos/{owner}/{repo}/pulls/<PR番号>/reviews
gh api repos/{owner}/{repo}/pulls/<PR番号>/comments
# 会話タブのコメント
gh api repos/{owner}/{repo}/issues/<PR番号>/comments
```

取得したら、**指摘を1件ずつ番号付きで一覧化**して提示する。各指摘について「レビュアー名・対象ファイル/行・指摘の要旨」をまとめ、解決済みスレッドは除外する。

---

## ステップ2: 指摘をトリアージする

各指摘を読み、コードを確認したうえで以下のいずれかに分類し、**一覧表で提案してユーザーの合意を得る**：

| 分類 | 意味 | その後のアクション |
|------|------|-------------------|
| **対応** | 指摘が妥当。修正する | 修正実装 → 対応した旨の返信 |
| **リジェクト** | 指摘に従わない。設計意図・責務分担などの根拠がある | 根拠を添えた返信のみ |
| **要相談** | 判断がユーザーに依る（仕様判断・トレードオフ） | ユーザーに判断を仰ぐ |

トリアージの判断材料として、必要なら該当コードや関連実装を読んで裏取りする。指摘の内容を鵜呑みにせず、実際のコードで妥当性を確認すること。

---

## ステップ3: 対応分を修正実装する

「対応」に分類された指摘を修正する。

- 修正はまとめてコミットしてよいが、無関係な変更を混ぜない
- コミット・push は git-commit スキルの規約（Conventional Commits・日本語）に従う
- 修正後、どのコミットでどの指摘に対応したかを控えておく（返信文に含めるため）

---

## ステップ4: 返信文を作成する

指摘ごとに返信文を起草し、**投稿前に必ず全文をユーザーに提示して確認を得る**。

### 返信の規約

- **先頭にレビュアーへのメンション**を付ける：`@<レビュアーのアカウント名> `。AI レビュアーも同様（`@gemini-code-assist`、`@claude` など）
- 日本語で、実装者としてのリスペクトと感謝を保ったトーンで書く
- **対応した場合**: 何をどう修正したかを簡潔に書き、対応コミットのハッシュを添える
  > @reviewer ご指摘ありがとうございます。〜のため、…するように修正しました（abc1234）。
- **リジェクトする場合**: 感謝したうえで、従わない理由（設計意図・責務分担・トレードオフ）を明確に書く。曖昧に濁さない
  > @reviewer ご指摘ありがとうございます。こちらは〜という責務分担の意図があるため、現状の実装のままとさせてください。
- 同一レビュアーの複数指摘でも、**インラインコメントにはスレッドごとに個別に返信**する

---

## ステップ5: 投稿する

ユーザーの確認が取れた返信を gh で投稿する。

```bash
# インラインコメント（レビュースレッド）への返信
gh api repos/{owner}/{repo}/pulls/<PR番号>/comments/<comment_id>/replies \
  -f body='<返信文>'

# 会話タブのコメントへの返信（通常コメントとして投稿）
gh pr comment <PR番号> --body '<返信文>'
```

- スレッド返信は `comment_id`（スレッド先頭コメントの ID）を指定する。ステップ1で取得した ID を使う
- 投稿後、投稿先スレッドと返信の対応関係を報告する

---

## ステップ6: PR 本文を更新する（必要な場合）

トリアージの結果、PR の説明と実装が乖離した場合（指摘対応で仕様が変わった、全指摘をリジェクトしてサマリーと食い違う等）は、PR 本文の更新も提案する：

```bash
gh pr edit <PR番号> --body '<更新後の本文>'
```

---

## 報告

最後に以下をまとめて報告する：

- 指摘の総数と内訳（対応 n件 / リジェクト n件 / 要相談 n件）
- 対応分の修正内容とコミット
- 投稿した返信の一覧
- PR 本文を更新した場合はその旨
